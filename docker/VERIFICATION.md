## 当前方案：仅 adb reverse

- 保留 `network_mode: host`、宿主 ADB server 和原有缓存布局；不提供 LAN 自动选路或双模式。
- ADB server 仅监听 `127.0.0.1:5037`，Metro 的**实际监听**仅为 `127.0.0.1:8081`；不向局域网开放开发服务器端口。
- 手机本开发包 `debug_http_host` 固定为 `127.0.0.1:8081`，由宿主脚本对所选设备建立 `adb reverse tcp:8081 tcp:8081`。
- 宿主客户端与容器固定 platform-tools 37.0.1；脚本检查客户端版本，并只读探测 server 协议 41，不声称能识别 server 的完整发行版，不自动替换或重启共享 server。

## 镜像缓存与原生构建

- 本次目录收敛后的镜像构建中，工具链、SDK、Android 依赖安装和补丁应用全部 **CACHED**。删除旧运行环境变量导致用户目录初始化及后续运行层重建，`node_modules` COPY 约 69 秒；这是复制已有依赖，不是重新执行 Yarn 安装。没有使用 `--no-cache` 或清除卷。
- 新 Docker Rust 入口真实通过：复用 OpenSSL 线程标记缓存，Cargo `--locked` release 检查 **0.13 秒**，复制 JNI 库后 `assembleDebug` 成功。原生构建 **2 分 39 秒**，1055 项任务中 309 项执行、538 项 from-cache、208 项 up-to-date，APK 大小及 SHA256 与前次一致。
- 先前 reverse 正式 `start` 复用运行容器的记录为 **1 分 12 秒**、14 项执行和 1041 项 up-to-date；这不是本轮新增的手机测试。
- 容器重建会丢失 `node_modules` 内原生依赖的可写层增量产物，但 Gradle/Cargo/OpenSSL/Metro 卷仍在；这不等于重装镜像依赖。

前一轮独立上下文缓存矩阵仍适用：相同输入重建 **4 秒**、全部 RUN/COPY 命中；应用配置或入口变化保持工具/依赖层命中；Android 清单描述变化仅重跑依赖阶段（约 112 秒、复用下载缓存）。业务与原生源码不进入镜像上下文。

## 历史故障与边界

2026-11-21 的失败排查中，手机曾处于 `Dozing`，本包有效网络阻断为 `DOZE|APP_BACKGROUND`；启动约 5 秒后规则撤销临时放行并主动复位 TCP。解锁前台后为 `TOP`、有效阻断为 `NONE`。该证据解释了当时重复的休眠断连，但不能代替每一次早期失败的独立对照；此前从 `NOT_VPN` 作出的 VPN 推断已纠正。现在已通过受控 reverse 实测，不再把网络状态与连接方式混为一谈。

此记录验证开发链路，不等同于登录、全部业务/ECH 网络功能、inspector、iOS 或发布回归。后续依赖升级所需的锁刷新、原生工程同步与业务/发布真机回归由用户按需执行。
